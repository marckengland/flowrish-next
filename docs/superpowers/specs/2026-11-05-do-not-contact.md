# Do not contact controls

The user approved address-based workspace contact suppression: block manual emails and cadence sends, including waiting jobs; preserve restrictions across duplicates, merge archives and reassignment; record who/why; require explicit review before clearing. No new dependencies, DeepSeek requests, real emails or widget activation. Baseline354b073; branchcodex/do-not-contact. Existing Git merge/push authorization persists. Preserve unrelated.serena/.spec-workflow. Existing-test corrections require user approval.

Use the existing CRM address normalization and address-based opt-out pattern documented by HubSpot. Add private ContactSuppression rows keyed by organization/email, with blocked state, revision, reason, actor and timestamps. Keep cleared rows and audit transitions rather than deleting evidence. Enable RLS and revoke public/browser grants; no browser SQL policies. A reviewed additive Prisma migration creates only this table, constraints and index, without business-data backfill.

A lead's relevant addresses include its primary/alternate addresses and directly archived merged sources. Existing merge rules prevent nested archive chains. If the bounded archive query overflows, fail closed. Any blocked relevant address stops that lead's outreach; checking an explicit recipient also catches merged-address replies. The registry is independent of lead IDs, so duplicate/reassigned/merged records cannot erase suppression. A newly added unrelated address alone is not globally blocked; old blocked addresses remain recorded.

Lead-detail UI reads current preferences through a scoped API, showing addresses and active restrictions. Read requires current workspace membership/lead visibility/leads:read; block additionally needsleads:write; clear additionally needsleads:delete. Mutations require captured user/workspace, same origin, bounded JSON, a snapshot version, reason and explicit confirmation. Recheck access and address/snapshot consistency around transactional writes and audit waits. Do not expose other lead names or their enrollment counts. Stale requests conflict instead of overwriting. Failed/uncertain writes require a status read and new review before another write; no automatic retry. Read-only users cannot mutate. Clear private state after access loss and ignore late replies after context changes.

Blocking atomically exits ACTIVE/PAUSED cadences for matching current/archived/duplicate lead targets, preserving enrollments/history. Clearing never resumes them. Serialize preference mutations and enrollment creation/resume with a workspace advisory transaction lock, so enrollment cannot miss a committed block. Enroll/bulk/resume require a fresh suppression check before and after writes; bulk skips blocked leads while preserving duplicate handling. No long transaction spans provider calls.

Cadence execution freshly checks suppression after waking and before effects; blocked work exits without send/task/history SUCCESS advancement. A block observed at final email delivery also exits the job without retrying outreach. The shared sendEmail boundary checks all callers initially, after token refresh, after provider/database preparation waits and immediately before Gmail/Microsoft delivery mutations. Microsoft authorization callbacks apply to background sends too. Manual templates and contextual replies retain all prior recipient/mailbox/version/permission protections. Incoming sync, stored conversations and callback records remain available. Already accepted provider actions cannot be recalled; the final database check cannot atomically cancel a provider request already in flight.

Recovery keeps suppression data/enforcement, pauses contact writes and new outreach through a tested fail-closed switch. Never redeploy the old unrestricted sender or delete blocked rows. Leave the additive table/migration in place. Apply synthetic schema offline with an explicit loopback-only copied config and owned Docker database; never root prisma db push. Full Node22 tests/lint/build then strict/fast types, extended mocked browser rehearsal retaining100 existing scenarios, synthetic PostgreSQL concurrency/privacy/rollback proof, one fresh branch review, merge/push and exact CI/deployment read-only verification. Production widget stays disabled.

Deferred: public self-service unsubscribe links, automated consent classification, SMS/phone dialer controls, globally timed provider cancellation, new role grants, and contact retention/erasure policy. Existing callback and inbound workflows are not contact consent collection. Design tradeoff: clearing a block needs an extra authorized review; workspace serialization limits concurrent preference/enrollment writes while protecting the opt-out invariant.
