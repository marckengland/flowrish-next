# Merge-aware reply detection

User-approved scope: route messages addressed from archived lead emails to the current retained lead only when unambiguous; hold conflicts for explicit review; stop eligible matching cadences and keep follow-up sending approval. No dependencies, DeepSeek calls, widget activation, emails sent, or real business-data verification writes. Use existing Next/Prisma/Zod/React/Vitest/Playwright. Session authorizes integration after checks.

One shared bounded resolver matches case-insensitive, trimmed email and altEmail on active leads and immutable merged archives, within one workspace. Multiple sources pointing to one active retained lead count as one target. Soft-deleted unmerged rows are ignored. Inactive, foreign, dangling or chained merge destinations and a source-cap overflow never auto-route. Existing addresses and provider settings are unchanged.

Sync persists mailbox-scoped EmailMessage first. Reply reconciliation owns activity linking, routing metadata, last activity, matching cadence exits, pending approval suggestions, and audit in a single transaction per stored message. It uses current mailbox/member identity, locks sorted source/target leads before the message, rechecks match/access after waits, and preserves existing human/thread/recipient/timestamp checks. Processed decisions replay without duplicate activities, suggestions, stops or audit. Already-linked legacy activities are retained rather than silently moved. Ambiguous messages remain unlinked; no cadence is changed until identity is resolved. No automatic draft generation or send occurs.

A nullable EmailMessage.leadRouting JSON column separates server decisions from provider replyMetadata. Bounded routing metadata holds state, reason, mailbox identity, matched address, and manual receipt. No duplicate message content or candidate names are stored. Existing table RLS is enabled with no browser policies, so the server-owned data remains inaccessible directly to browser roles. A partial pending index is provided; inbox responses are limited to 100 messages. No row backfill or existing message/body edits in migration.

Follow-up inbox gains an owner-scoped email-match review section: list up to100 pending messages, explicitly preview current accessible matches (up to20), choose a lead or dismiss, check a review acknowledgment, and confirm. Current member/read/write permission, mailbox ownership, same-origin bounded JSON, expected user/workspace, message/version and candidate membership are rechecked transactionally. The version includes matching sources, targets and visible choices. Uncertain writes retain the same request UUID/version/action; explicit retry returns the same receipt and never relinks. Inaccessible candidates are redacted. Invalid or over-limit alias graphs require administrator correction; dismissal is available. Role/mailbox/account changes clear private client state and reject stale actions. Source/candidate changes require a new preview.

Verified incoming-source routing can authorize a contextual draft/send to that source address when the activity, mailbox, reviewed decision and current lead lineage still agree. It does not broaden unrelated recipients or create mailbox aliases. The user must still generate/review a draft and explicitly send; tests mock all providers.

Safety switch pauses automatic linking/cadence changes and manual resolution while keeping new mail pending for review. Existing verified-source drafts keep their normal approval checks. Prepare and test a local pause patch. No automatic destructive data undo: routing decisions have audit/history; any correction after later work needs exact per-message operator review. Keep routing metadata, queued reviews and schema on code disable. Deferred: automatic record merging, mailbox forwarding/aliases, historical backfill, cross-mailbox transfers, unbounded matching and automatic sending.
