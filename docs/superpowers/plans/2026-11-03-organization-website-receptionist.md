# Organization website receptionist

**Approved scope:** Embeddable receptionist for each organization's own website/customers. Answer from approved business knowledge, collect explicitly confirmed callback requests for staff review, enforce request/token and spam limits, off until explicitly enabled. Verification mocks only; never retrieve/decrypt/use saved real provider keys or make live AI/Twilio calls. Existing session authorization covers tests/fixes/merge/deployment. No dependency or existing-test changes without approval.

**Design/prior art:** Conventional cross-origin iframe isolation, exact allowed website origins and server-controlled short-lived bearer sessions. Static loader creates a launcher; opening it loads a nonce-CSP iframe with scripts from Flowrish only. The iframe requires an allowed parent postMessage handshake (origin+source checked), then requests its own same-origin API without app cookies. Browser origin checks constrain embedding; they are not bot identity. Durable per-organization quotas remain authoritative even when IP limits/Redis can be bypassed. No untrusted HTML rendering.

## Stored data / controls

- WebsiteReceptionistConfig: organizationId PK, publicId uniqueUUID generated on explicit save, enabled=false, allowedOrigins exact HTTPS origins(max5), dailyMessageLimit default5/max20, dailyTokenLimit default20000/max200000, dailyCallbackLimit default10/max50, updatedAt configversion. Enable requires saved valid business, current organization AI enabled/valid, and at least one receptionist-approved published library document; explicit spending acknowledgement. Save never calls/decrypts provider. Phone receptionist toggle independent. All current orgs remain disabled.
- WebsiteReceptionistUsage: organizationId/dayUTC/scope (org or ip:HMAC64) compositePK, sessions/messages/reservedTokens/callbacks nonnegative, updatedAt. Atomic quotas under config-row lock: org20 starts/day, IP5 starts/day; org configured messages/tokens/callbacks; IP10 messages/day and3 callbacks/day. Public AI reserve fixed9656 (inputmax9000+overhead256+outputmax400) per attempt, never refunded; org AI's existing quotas also apply. No deployment/global-key fallback for public AI.
- WebsiteReceptionistSession: idUUID/org, tokenHash SHA256unique, ipHash (HMAC existing server encryption key, scoped org+startUTCday), siteOrigin, configVersion, createdAt/expiresAt30min, turns0..6, closed bool, inFlightIdUUID/leaseExpiresAt30sec, lastRequestIdUUID/lastResponseJSON(public reply only), callbackSubmittedAt nullable. No visitor questions/history stored. Client holds only memory token/history. Config changes invalidate sessions immediately. Claim in transaction before model call; cached requestId retry free, pending conflict409; expired leases close chat with a distinct recoverable code while keeping callbacks available, conservative limits survive concurrency and restarts. Provider call outside DB transaction, finalize only matching lease.
- WebsiteReceptionistCallback: idUUID/org, sourceSessionId unique(org/session) snapshot identifier intentionally no session FK (cleanup must retain confirmed requests), name<=120/phoneE164/reason<=1000/siteOrigin, status pending/reviewed/dismissed, consentedAt server timestamp, updatedAt/version, reviewedById nullable. One confirmed callback per session; deletion cannot recreate via same live token (session marker). No leads/tasks/activities/email/calls. Staff explicitly mark reviewed/dismissed or delete. Callback retained until staff/org removal.
- All four tables RLS enabled and PUBLIC/anon/authenticated grants revoked. Org FKs cascade. Daily cleanup via existing Inngest: delete sessions expired>24h and widget quota rows older2 UTCdays; never delete callbacks/org AI usage.

## Public API (no app session)

Exact `/api/public/website-receptionist/[publicId]/embed` GET: validates UUID, enabled config+allowed query origin, returns standalone HTML with nonce script/style CSP and frame-ancestors configured origins. Only this exact GET/HEAD path carves X-Frame-Options DENY; all other app pages retain protection. Generic unavailable response otherwise frame-ancestors none. Static assets `/receptionist-widget.js` loader and `/receptionist-widget-frame.js` frame runtime. Loader data attribute data-flowrish-receptionist=publicUUID; baseURL derived from its own scriptURL. It sends parent-origin handshake only to the known iframe window with targetOrigin=Flowrish origin. Frame verifies event.source===parent and event.origin===configured siteOrigin, and must be framed; no token/session call on direct navigation.

POST `/session`: strict {siteOrigin,website:''}; no auth cookie dependency. Require same-origin Origin header, valid server-observed IP, allowed site, enabled config, durable daily starts. Return {data:{token64hex,businessName,greeting,expiresAt,turn:0}}. Honeypot nonempty rejected before counters. No AI.
POST `/message`: Authorization Bearer token64hex, strict {requestIdUUID,expectedTurn0..6,question1..1000,history:string[](max4,each1000,total4000UTF8),website:''}. Minimum session age2sec. Match config/publicId/origin/IP/version/expiry; reserve durable message/tokens and claim turn, check current enabled valid org-provider metadata before any decryption. Output {data:{reply1..600,turn1..6,canMessage:boolean}}. No source titles/IDs, private FAQs, provider details, arbitrary assistant history or client organization ID. Only caller history is untrusted data; helper retrieves complete approved published library paragraphs within a 2200-byte facts budget (manual receptionist text and oversize paragraphs excluded), bounded input/output, no tools. Plain reply generation requires organization provider and clamps input9000/output400, timeout8sec. Missing/failed/overbudget AI gives safe callback guidance, never global fallback. All failed attempts count conservatively; callback remains available.
POST `/callback`: Bearer token, strict {fullName,phone,reason,confirmed:true,website:''}; user first sees readback and consent checkbox in UI. Same session/quotas/minage2sec; duplicate returns {data:{received:true}} without overwriting or re-consuming. Commit only pending callback+marker/counters; no AI/CRM. Response says request sent to business for review, no appointment or outbound call implied.
All responses no-store/nosniff; generic safe errors; no CORS credential allowance or public app-auth exceptions beyond exact route+method set. Middleware bypasses Supabase only for these paths after general API rate layer; service DB caps fail closed regardless Redis state. No raw IP/token/config/provider errors in logs.

## Admin API (fresh membership + effective admin:settings)

GET/PUT `/api/admin/website-receptionist`: GET {data:WebsiteReceptionistAdminData}; settings nullable, readiness booleans/count, currentUTCusage. PUT strict enabled/origins/limits/expectedUpdatedAt(null ifnew)/acknowledged; versionCAS, no real-key reads/calls. Response same DTO. Settings component has explicit consent/Save, separate enable checkbox, origins textarea, caps, copyable public script snippet. No automatic enabling or test connection.
GET `/api/admin/website-receptionist/callbacks?status=pending|reviewed|dismissed|all&page=1`:20 records/page, safe org-scoped fields. PATCH `/callbacks/[id]` {action:review|dismiss,expectedUpdatedAt}; DELETE scoped after UI confirmation. Staff UI list/detail with static state labels, no send/dial automation.

## Tradeoffs / rollback

IP+honeypot+session/cap protections constrain abuse; they do not prove a visitor is human. No CAPTCHA/provider dependency in this release. Conservative widget token reservations can allow fewer replies than the nominal message cap (default at most2 attempted replies/day from20000 allowance); existing organization caps also apply. History is untrusted user-only context, not a trusted transcript. Callbacks are structured forms with explicit review/consent, separate from AI reply extraction. Staff review does not create leads/tasks automatically.

Baseline main6cd04b1. Record disabled/no-table before-state read-only. Revert application code while preserving additive Prisma/migration; leave confirmed callbacks/metadata intact. To urgently disable after opt-in, set configenabled=false (invalidates active sessions), preserving prior metadata/version and no credentials. Build and test rollback before shipping. Do not change existing business/provider settings, enable live widget forverification, drop data, edit applied migrations, restorefullDB orforcepush.
