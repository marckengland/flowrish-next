# Receptionist installation checker implementation plan

**Goal:** Let organization administrators explicitly check a public website for their standard Flowrish widget snippet and receive actionable setup guidance without loading the widget, sending an AI message, or enabling reception.

**Architecture:** An authenticated same-origin POST reads the current organization's saved website configuration, checks exact allowed origins, and fetches at most four bounded HTTPS responses using DNS-validated, pinned connections. A bounded source scanner identifies active classic script tags. Results are transient; no business data or settings are written. Existing Redis supplies one check per organization per 30 seconds.

**Tech stack:** Existing Next.js/React/Zod/Prisma/Redis; Node 22 DNS, HTTPS, networking, and streams. No dependencies, migrations, provider calls, or scheduler changes. User approved the proposed checker through “go”; use the established inline execution and existing authorization for testing, fixes, merge, push, and deployment.

## Scope and decisions

- Embed the checker below the existing snippet in guided setup's simulation/install step. It uses the saved public widget ID, allowed origins, and configuration version. No automatic traffic on mount, no widget activation, and no launch requirement changes.
- Accept one public HTTPS page URL, maximum 2,000 characters, with default port, a dotted DNS hostname, no credentials, query, or fragment. Saved exact origin membership is required before DNS/network traffic. Mismatches produce guidance without a request.
- Resolve all DNS answers; reject the host if any answer is not a permitted globally routable IPv4 or IPv6 address. Block loopback, private, link-local, metadata, multicast, reserved/documentation, translation/tunnel, and mixed public/private destinations. Pin the chosen address in HTTPS lookup, preserving the hostname for TLS/SNI and Host. Do not reuse the existing account-research text fetcher because this feature must preserve script tags and pin the actual connection's address.
- Revalidate URLs, saved origins, DNS, and pins after every redirect. Stop after three redirects, eight total seconds, 512 KiB, or 16 KiB response headers. Send no credentials, cookies, authorization, referer, request body, or compressed-content request. Accept successful identity-encoded `text/html` only; never execute scripts or fetch linked resources.
- The source scanner ignores comments, raw text, templates/noscript, and foreign namespaces. It recognizes quoted/unquoted/case-insensitive attributes, first-attribute semantics, common/numeric entities, active classic script types, and duplicates. Require the standard absolute HTTPS script source; unsupported/custom embedding gets guidance rather than a “working” verdict. Ignore inline strings and encoded examples. A source match does not prove JavaScript execution, CSP compatibility, browser connectivity, AI readiness, or a successful conversation.
- Require current local Settings permission and membership before work and again after outbound traffic. Compare the submitted saved-settings version before and after the check; changed settings require a reload. Read only public widget ID, allowed origins, enabled flag, and updatedAt. Do not read/decrypt AI credentials or load approved documents.
- Fail closed if Redis is unavailable; return 429 if the organization cooldown is occupied. Redis keys contain the organization identifier only. Existing business/widget/CRM/usage tables remain unchanged. Verification mocks Redis and every outbound website request.
- Return only safe URLs, timestamp, saved version/ID, fixed status, and bounded snippet counts. Do not return/store page HTML, third-party widget IDs, response headers, IPs, or internal diagnostics. UI clears results when URL/settings change and rejects mismatched/stale responses, with abort/unmount protection.

This static-source design makes tag-manager/JavaScript-only installs and runtime CSP confirmation harder to verify later; those need an explicitly isolated browser check, not broader server fetching.

## Review focus

- DNS rebinding, IPv6/IPv4 encodings, redirects, TLS hostname checks, streaming and time bounds must not allow private-network access or unbounded work.
- Source examples/inert scripts, wrong IDs/hosts, duplicates, modules/nomodule, and malformed attributes must never be called a working installation.
- Fresh local organization authority, saved configuration versions, exact origins, and cooldown must gate every network request and returned result.
- Do not return private page content/IDs/IPs or diagnostics, leak previous results after edits, or silently enable/test the widget or AI.
- Keep the existing guided setup simulation, unsaved-change handling, launch acknowledgements, and tests working.
